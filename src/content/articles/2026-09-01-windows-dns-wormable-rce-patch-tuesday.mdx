Once a month, Microsoft ships a batch of security fixes for Windows and its surrounding software. The event has a name, Patch Tuesday, and most months it passes without much notice outside IT departments. August 2026 was not most months.

On August 11, 2026, Microsoft's Patch Tuesday release addressed 421 vulnerabilities across its product line, one of the larger batches of the year. Buried in that count were two bugs that security researchers flagged immediately, for very different reasons. One is a critical flaw in Windows DNS Server that Microsoft itself describes as "wormable." The other is already being used by attackers in the wild, and its official severity rating does not add up.

Here is what happened, why the technical details matter, and what the historical precedent tells us about how seriously to take it.

## CVE-2026-62878: what "wormable" actually means

CVE-2026-62878 is a remote code execution vulnerability in Windows DNS Server, the software that translates human-readable domain names into the numeric addresses computers use to find each other on a network. It carries a CVSS score of 9.8 out of 10, near the top of the scale, and it is a stack-based buffer overflow.

A stack-based buffer overflow is one of the oldest categories of software bug, and one of the most dangerous. In plain terms: a program sets aside a fixed, small amount of temporary memory to hold a piece of incoming data, expecting that data to be a certain size. If an attacker sends more data than the program expects, and the program fails to check the size before copying it in, the extra data spills past the boundary of that memory space. That overflow can overwrite adjacent memory, including the part of the program that tracks what instruction to execute next. A carefully crafted overflow can hijack that instruction pointer and make the program run code the attacker supplied instead of its own.

What makes CVE-2026-62878 especially severe is the combination of conditions attached to it. According to the Zero Day Initiative's technical review of the August 2026 release, the bug is remotely exploitable, requires no authentication, and needs no user interaction of any kind. No employee has to click a malicious link or open a bad attachment. A vulnerable DNS server simply has to be reachable over the network, and an attacker can trigger the flaw directly, gaining elevated privileges on the machine.

Microsoft's own security advisory for this vulnerability describes it as wormable. That word is doing a lot of work, and it deserves an explanation.

### Why "wormable" is a different category of dangerous

Most vulnerabilities require some deliberate action, by an attacker or an unwitting victim, to spread from one machine to the next. A wormable vulnerability removes that requirement. If a piece of malicious code can exploit the flaw to compromise one server, and that compromised server can then use the same flaw to compromise other reachable servers, the infection spreads on its own. No human has to do anything after the first infection takes hold. It propagates the way a biological virus spreads between hosts, hence the name.

This is a uniquely dangerous property because it removes the usual constraints on how fast and how far an attack can travel. A phishing campaign is limited by how many people click a link. A wormable exploit is limited only by how many vulnerable, reachable machines exist on the internet, and how fast the exploit code can reach the next one.

DNS servers make this risk worse rather than better, for a structural reason: unlike most internal business systems, DNS servers often have to be exposed to the public internet by design. A DNS server that only answers requests from inside a private network cannot do the job the wider internet needs it to do, which is resolving domain names for anyone, anywhere, who asks. That necessary public exposure is exactly the property a wormable exploit needs to find its first victims and keep spreading.

As of the patch's release, CVE-2026-62878 was not listed as actively exploited. That is the good news in an otherwise alarming writeup. But the history of wormable Windows vulnerabilities gives good reason not to treat "not yet exploited" as "not urgent."

### The precedent: Conficker and EternalBlue

Two historical incidents illustrate what a wormable Windows bug can do once someone builds a working exploit for it. Both are offered here as analogies for the kind of failure this class of bug produces, not as claims that they are the same vulnerability or the same incident as the 2026 CVEs.

In 2008, a worm known as Conficker exploited a buffer overflow in the Windows Server service, spreading across corporate, government, and home networks worldwide with no user interaction required. It went on to infect millions of machines and remained a persistent nuisance on unpatched systems for years afterward.

In 2017, a Windows SMB (file-sharing protocol) vulnerability, also rooted in a buffer overflow, became the foundation for an exploit called EternalBlue. That exploit was subsequently weaponized into two of the most damaging pieces of malware in recent history: WannaCry and NotPetya. WannaCry alone reportedly struck more than 200,000 computers across 150 countries in a single weekend, encrypting files and demanding ransom payments, disrupting hospitals, logistics firms, and government agencies in the process.

Both incidents share the same underlying failure class as CVE-2026-62878: a buffer overflow in a Windows network service, exploitable with no user interaction. That does not mean CVE-2026-62878 will play out the same way. No public exploit is confirmed to exist for it yet. But it means the pattern is a known and proven one, and the industry has watched it happen at scale before.

## CVE-2026-68820: an actively exploited bug with a score that does not add up

The second notable fix in the same batch is CVE-2026-68820, an elevation-of-privilege vulnerability in the Windows Ancillary Function Driver (AFD) for WinSock, the low-level component that manages network socket connections for Windows applications. Its CVSS score is 7.0, meaningfully lower than the DNS Server bug.

Unlike CVE-2026-62878, this one does not grant an attacker initial access to a system on its own. It is a privilege escalation bug: something an attacker uses after they already have a low-level foothold, for example by getting a victim to click a phishing link that runs unprivileged code. From that limited starting point, CVE-2026-68820 lets an attacker jump straight to SYSTEM-level access, the highest privilege tier on a Windows machine, effectively full control.

What makes this bug the more immediately newsworthy of the two is that Microsoft confirmed it was already being exploited in the wild as a zero-day, meaning attackers were using it before a patch existed.

### The inconsistency

Here is the detail that caught the attention of the Zero Day Initiative's researchers: Microsoft's own CVSS scoring for CVE-2026-68820 lists its "Exploit Code Maturity" as "Unproven," a category that, by definition, indicates no known working exploit exists. Microsoft made that assessment in the very same advisory where it confirmed the vulnerability was being actively exploited.

Those two statements cannot both be straightforwardly true. If a vulnerability is being actively exploited, a working exploit exists by definition, whether or not it has been publicly disclosed or reverse-engineered by outside researchers. The Zero Day Initiative's write-up on the August 2026 release called this discrepancy out directly, noting the mismatch between the stated exploit maturity and Microsoft's own confirmation of active exploitation.

<Callout label="Why this discrepancy matters beyond one CVE">
  CVSS scores are widely used by security teams to triage which patches get applied first when hundreds of fixes land in a single batch. A metric like "Exploit Code Maturity" is meant to help teams judge urgency. When that metric understates a bug's real-world status, teams relying purely on the number, rather than reading the underlying advisory text, risk deprioritizing a vulnerability that is already being weaponized against real targets.
</Callout>

The practical lesson is not that CVSS scores are useless. It is that a single number is a summary, not a substitute for reading what the vendor's advisory actually says about exploitation status. In this case, the qualitative text ("actively exploited") told a more urgent story than the quantitative subscore ("Unproven") sitting right next to it.

## What this means if you do not run a Windows server

Most readers are not systems administrators. Here is why this still matters.

DNS is one of the quiet, foundational layers of the internet. Every time a browser loads a website, a DNS lookup happens first, translating the address typed into the browser into the numeric address the underlying network actually uses. Businesses, universities, hospitals, and internet service providers all run DNS infrastructure, much of it on Windows Server. A wormable compromise of DNS infrastructure has the potential to disrupt services that people never think about until they stop working: email delivery, website availability, internal corporate networks, and services that depend on those networks in turn.

The WannaCry incident referenced above is the clearest illustration of this ripple effect. Most of the people whose hospital appointments were disrupted in 2017 had never heard of the SMB protocol and never will. The vulnerability that caused the disruption was several layers removed from anything they interacted with directly. That is the nature of infrastructure-level security bugs: the people affected are rarely the people who could have prevented it.

For a general reader, the practical takeaway is smaller and more mundane: keep operating systems and software updated, because vulnerabilities like these are exactly what those routine update prompts exist to fix, even when the update itself never explains why it matters.

For anyone responsible for infrastructure, particularly internet-facing DNS servers, the takeaway is direct: patch CVE-2026-62878 now, do not wait for a routine cycle, and treat CVE-2026-68820 as already weaponized regardless of what its exploit-maturity subscore suggests.
